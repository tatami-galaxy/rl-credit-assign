# Repository guidelines

This repository explores LLM reasoning through small, incremental experiments.

- Keep code simple, concise, and human readable. Prefer clarity over cleverness.
- Build one experiment at a time. Add only what the current experiment needs.
- Use clear names and straightforward control flow. Avoid unnecessary abstractions, wrappers, and configuration layers.
- Refactor working code when it improves simplicity or readability, preserving its behavior.
- Verify changes with checks appropriate to their scope. Keep experimental settings and results easy to inspect and reproduce.

- There is a `thoughts` folder which contains my rough thoughts and notes. There's no need to read it.


# Response guidelines

I'm mostly interested in exploring research ideas. The ideas are not necessarily mine or unique, they may simply be things I'm interested in. If I'm proposing a new idea, you do not have to validate it or explicitly look for strengths in it. Be as impartial and direct as possible. If an idea is already well executed or invalidated by existing evidence then that saves us a lot of time. 

While reporting results, there's no need to be insecure about negative or inconclusive results. If the results are negative be very clear about that. We are not trying to get positive results any way we can. Our goal is to do good research which also includes negative results. 


# Literature review

While searching for papers, prioritise papers published at top conferences or from frontier labs or well known universities or from well known researchers. These are usually good signals. But good papers can come from anywhere, and might be preprints on arxiv for example.
